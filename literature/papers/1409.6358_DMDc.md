# Dynamic mode decomposition with control — DMDc (2014)

- **Authors / venue:** J. L. Proctor, S. L. Brunton, J. N. Kutz (Institute for Disease Modeling / Univ. Washington). SIAM J. Applied Dynamical Systems 15(1), 2016.
- **Links:** https://arxiv.org/abs/1409.6358 · implementation in PyDMD (`DMDc`, https://github.com/PyDMD/PyDMD)
- **Source read:** tex (arXiv e-print)
- **Thread:** 1 ROM (linear, with input)

## Summary
It extends DMD to actuated systems: `x_{k+1} = A x_k + B u_k`, identified from state snapshots X, X' and input snapshots Υ. The system is solved by an SVD of the stacked `[X; Υ]` (with truncation) and projected onto the POD modes of X'. This separates the intrinsic dynamics (modes/eigenvalues of A) from the effect of actuation. Works whether B is known or unknown.

## Benchmark fields
| Field | Value |
|---|---|
| Input geometry | Any (vector snapshots; POD-based) |
| Exogenous conditioning | **Native: `B u_k`** with u = phi(t) — exactly FlameBench's input |

| Prediction target | Next state (linear) |

## Relevance to FlameBench
**Must-include linear baseline**, the "floor" every model must beat. Our `pod-arx` with `n_past=1`, `poly_degree=1` is already DMDc in POD coordinates, with u = phi(t+1). Note: `PODARXModel` currently uses only `phi_future`, not the phi history. So DMDc needs no new class — just a config — plus reporting the eigenvalues/modes of the fitted A. It is the classical system-identification reference combustion people know. It also connects naturally to flame transfer function (FTF) identification from broadband/sine-sweep forcing — the typical use of such forced-flame data.
