# Eagle: Large-Scale Learning of Turbulent Fluid Dynamics with Mesh Transformers (2023)

- **Authors / venue:** S. Janny, A. Béneteau, M. Nadri, J. Digne, N. Thome, C. Wolf (INSA Lyon / LIRIS, Sorbonne). ICLR 2023 (per the tex template).
- **Links:** https://arxiv.org/abs/2302.10803 · project page / code: https://eagle-dataset.github.io (verify)
- **Source read:** tex (arXiv e-print)
- **Thread:** 3 GNNs (+ 4 benchmark)

## Summary
Two contributions: (1) the **EAGLE dataset** — ~1.1M 2D meshes, RANS (Ansys Fluent, Reynolds-stress model) airflow generated by a 2D UAV flying over 600 procedurally generated floor profiles (step/triangular/spline), 990 steps per simulation, down-sampled to ~3.4k nodes per mesh, 270 GB; (2) a **mesh transformer**: GNN encoder, then same-size k-means **clustering + graph pooling** to coarse tokens, then global multi-head self-attention among clusters, then a decoder upsampling back to nodes to predict velocity and pressure at t+1.

## Benchmark fields
| Field | Value |
|---|---|
| Input geometry | Native unstructured (dynamic) mesh |
| Exogenous conditioning | Indirect: the **moving flow source (UAV) is an exogenous driver** of the flow, passed as node types / future mesh geometry. No scalar-forcing mechanism |
| Latent reduction | Clustering to a fixed set of cluster tokens (similar in spirit to Transolver slices, but geometric rather than learned) |
| Prediction target | Next-step velocity and pressure |
| Rollout & stability | AR rollout, evaluated at long horizons; MGN-style training |
| Demonstrated scale | ~3.4k nodes average, 990 steps, 1,200 simulations |
| Datasets / physics | EAGLE (turbulent RANS airflow with a moving source), MGN CylinderFlow, ScalarFlow (real smoke) |
| Code + license | See project page — LICENSE_TBD |
| Integration effort | Medium (clustering is a one-off for our fixed mesh) |

## Relevance to FlameBench
Side note: for the grid baseline (DilResNet), EAGLE projects **CylinderFlow onto a uniform 256x64 grid** — the same `grid_shape [256, 64]` as in our `train.json` for `fno3d`/`unet`. Our configs were probably inherited from a CylinderFlow setup, which explains ISSUES #4. EAGLE's appendix describes that projection step and is a reference for doing the same with our 21334 cells.

Two uses. (a) **Model:** the cluster-pool + global-attention design is a middle ground between MGN (local) and Transolver (learned global slices); it could be an optional GNN-transformer hybrid. (b) **Benchmark design:** EAGLE is the closest ML benchmark with an **externally driven unsteady flow** (moving source), and a good template for describing data, splits and metrics. Lower priority than MGN/BSMS/Transolver as a model.
