# POD-DL-ROM: enhancing deep learning-based reduced order models for nonlinear parametrized PDEs by proper orthogonal decomposition (2021)

- **Authors / venue:** S. Fresca, A. Manzoni (Politecnico di Milano). Computer Methods in Applied Mechanics and Engineering 388 (2022).
- **Links:** https://arxiv.org/abs/2101.11845
- **Source read:** tex (arXiv e-print)
- **Thread:** 1 ROM + sequence

## Summary
Two-step reduction. (1) **Randomized SVD / POD** to N modes (N large-ish, e.g. 64-256). (2) A DL-ROM on the POD coefficients: a convolutional autoencoder compresses them to a tiny nonlinear latent n (≈ n_mu + 1). A feed-forward net maps `(t, mu) → latent`, and the decoder maps back to POD coefficients, then to the field. The encoder is only used in training. Multi-fidelity pre-training cuts training cost.

## Benchmark fields
| Field | Value |
|---|---|
| Input geometry | Any mesh (POD works on the raw FE/FV vector); tested on unstructured FE meshes |
| Exogenous conditioning | **Static parameters mu only**; the map is `(t, mu) → u(t)`, not autoregressive. A time-varying phi(t) does not fit directly. You would need to replace `(t, mu)` with a phi-history window, which turns it into our `pod-*` sequence models with a nonlinear bottleneck |
| Latent reduction | **POD (rSVD) + nonlinear AE on the POD coefficients** |
| Prediction target | Absolute field at time t (space-time parametric map) |
| Rollout & stability | None (non-AR) — no error accumulation, but no causal dynamics |
| Demonstrated scale | FE meshes of O(10^4-10^5) dofs; advection-diffusion-reaction, monodomain cardiac PDE-ODE, elastodynamics, **unsteady NS around a cylinder** |
| Datasets / physics | See above |
| Code + license | No public repository stated in the paper |
| Integration effort | Medium: reuse our `PODReducer` (already randomized SVD) + a small conv/MLP AE on coefficients |

## Relevance to FlameBench
Our `pod-transformer`/`lstm`/`pod-arx` are already "POD + sequence model". POD-DL-ROM adds the idea of a **second, nonlinear compression of a larger POD basis**. That is a cheap upgrade path for the POD family (e.g. rank_POD=64 → AE to latent 8 → transformer), and it sits between our `pod-transformer` (linear) and `ae-transformer` (full AE on 21k cells). The static-(t,mu) formulation itself is **not** a FlameBench candidate. Cite as the Italian/European ROM reference.
